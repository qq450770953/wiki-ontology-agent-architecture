## 已知否定性事实（防自我美化）

- `ontology-enterprise` 参考实现**不在本机**，其 CLI 能力（`type define`、`action run` 等）均引自 architecture.md §11.1 自述，本仓未复现验证。
- llm-wiki 验收矩阵（research/llm-wiki-graph-index-design.md §9）7 项运行时状态全部为「待实现验证」，截至 2026-10-26 无一执行。
- §11.2 的 T1–T6 全部「未开始」。
- 2026-10-26 之前本仓 24 个受版本控制文件中源代码文件数为 **0**；当日新增 `prototype/`（2 个 .py）为首批可运行代码，性质是**接口原型**，不改变「设计文档仓」定位（见 AGENTS.md §1 补充说明）。
- **检索侧无任何生产组件**：没有 Elasticsearch、Milvus、Qdrant、Neo4j 实例；向量路是 TF-IDF 哈希替身，图谱路是内存图，重排是启发式。`CYPHER_EQUIVALENTS` 只是待实现的语义草稿，未在 Neo4j 上执行过。
- **`HttpEmbedder` 只验证了协议行为**：用本地 stub 服务验证了请求构造、响应解析（OpenAI / TEI 两种）、条数与维度校验、4xx 不重试、不可达降级；**没有任何真实 embedding 权重参与过指标计算**。
- **融合在本语料上是负收益，不是正收益**：`--ablation` 实测 R@1 单路 bm25 0.548，加 vector 降到 0.508，加 graph 降到 0.403，三路全开 0.427。根因是 RRF 只用名次不用分数——低精度路的一条错误 rank-1 与高精度路的一条正确 rank-1 拿到同样的 `1/61`，会把准确路的 top-1 挤掉。不得表述为「已验证混合检索收益」。
- 评估集 62 条、语料 233 chunk，规模仍不足以支撑统计显著性；指标只用于回归对比，不得外推为业务效果。扩样（25→62 条）使 bm25 R@1 从 0.520 变为 0.548，这是**样本变化**而非算法改进。
- 无真实 ETL：语料是仓库自身文档，未接工单库、聊天记录或代码库；清洗、去重、增量更新、失效删除均未实现。
